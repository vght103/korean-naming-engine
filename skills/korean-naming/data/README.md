# 인명용 한자 데이터 (`inmyeong_hanja.tsv`)

출생신고에 쓸 수 있는 한자 전체를 한 표로 정리한 데이터다. 글자마다 인명용 발음, 원획(原劃), 획수오행, 부수 자원오행(휴리스틱), 훈음을 붙였다.
`scripts/build_hanja_table.py`로 언제든 같은 결과를 다시 만들 수 있다. 출력은 코드포인트 순으로 정렬되며, 입력이 같으면 바이트 단위까지 같다.

| 항목 | 값 |
|---|---|
| 행 수 | **8,094자** (머리행 제외) |
| 교육용 기초한자(E) | 1,800자 (이 가운데 73자는 인명용 표지 N도 함께 붙음) |
| 인명용 전용(N만) | 6,294자 |
| `kKoreanName` 연도 | 2015년 목록 6,249자, 2018년 추가 118자 |
| 훈음(`hun`) 채워진 행 | 7,189자 |
| 생성물 sha256 | `06e440fb372ce4e5335e27830f040deefaf035b0f4ce6bb28300b014082de09b` |

## 1. 데이터 출처와 버전

| 자료 | 버전·고정값 | 라이선스 | 쓰는 곳 |
|---|---|---|---|
| Unihan (Unicode 18.0.0) | npm `@mandel59/mojidata@1.9.1`의 `dist/moji.db`. 패키지 `download.txt`에 `Unihan.zip` sha256 `4c93ea9c1f63…c63d43e`가 고정되어 있음. 이번에 쓴 `moji.db`의 sha256은 `c8cd4303…4c21ea6b`. | Unicode License v3 (mojidata 패키지: MIT AND BSD-3-Clause AND CC-BY-SA-2.1-JP AND Unicode-3.0) | 인명용·교육용 표지, 읽기, 부수·획수, 영문 뜻, 강희자전 위치 |
| libhangul `data/hanja/hanja.txt` | `https://raw.githubusercontent.com/libhangul/libhangul/main/data/hanja/hanja.txt` (2026-10-01 수신, sha256 `b1004034589f1357daaea3534a6136f6b5ef825afa8779886b20f0b7908bbe3b`). 이 환경에서는 GitHub API가 막혀 커밋 해시를 확인하지 못했으므로 sha256으로 고정한다. | BSD-3-Clause, Copyright (c) 2005,2006 Choe Hwanjin | `hun` 열(한 글자 항목의 "뜻 음") |

사용한 Unihan 필드는 다음과 같다.

- `kHangul`: 읽기와 표지. `N`은 대법원 인명용 한자표, `E`는 교육용 기초한자 1,800자, `0`/`1`은 KS X 1001/1002 수록 읽기, `X`는 표준에 없는 읽기다.
- `kKoreanName`: 인명용 한자표에 실린 해(2015 또는 2018).
- `kKoreanEducationHanja`: 교육용 기초한자 지정 연도(2007).
- `kRSUnicode`: 강희 부수와 나머지 획수.
- `kTotalStrokes`: 총획.
- `kKangXi`: 강희자전 쪽·자리 번호.
- `kDefinition`: 영문 뜻.

가족관계등록규칙은 교육용 기초한자를 인명용 한자에 포함하므로, 이 표는 `N` 또는 `E` 표지가 붙은 글자를 모두 담는다.

## 2. 다시 만드는 방법

```bash
# 1) Unihan DB (npm 레지스트리에서 받음, 약 100MB)
curl -sSLO https://registry.npmjs.org/@mandel59/mojidata/-/mojidata-1.9.1.tgz
#   integrity: sha512-cqAizyE6D+ZoSLViHCulervFs0AvTyW1TazSchxWUzQdSOvZBmKv9VXH+iQclOGd7JMWLSYCQBph9rVapzIj0Q==
tar xzf mojidata-1.9.1.tgz        # → package/dist/moji.db

# 2) 훈음 원본 (선택)
curl -sSLo hanja.txt https://raw.githubusercontent.com/libhangul/libhangul/main/data/hanja/hanja.txt
sha256sum hanja.txt               # b1004034…be3b 와 같아야 같은 hun 열이 나온다

# 3) 생성 (python3 표준 라이브러리만 사용)
python3 skills/korean-naming/scripts/build_hanja_table.py \
    --mojidb package/dist/moji.db \
    --out skills/korean-naming/data/inmyeong_hanja.tsv \
    --hun hanja.txt
```

실행하면 표준오류(stderr)에 다음 내용이 출력된다.

- 행 수
- 규칙별·플래그별 건수
- 기준 원획 42자 검증 결과
- `尙`/`尚` 비교

`--hun`을 빼면 `hun` 열만 빈칸이 되고, 나머지 열은 같다.

## 3. 열 설명

TSV는 UTF-8, 탭 구분, 따옴표 없음(`csv.QUOTE_NONE`)이다. 열 이름으로 읽기를 권한다. 뒤의 네 열(`radical_char` 이후)은 작업 지시서에 없던 추가 열이다.

| 열 | 뜻 |
|---|---|
| `hanja` | 한자 |
| `codepoint` | `U+XXXX` |
| `inmyeong_readings` | `N` 또는 `E` 표지가 붙은 읽기만 쉼표로 나열(예: 沇 `연,윤`) |
| `all_readings` | `kHangul`의 모든 읽기(예: 李 `리,이`, 여기서 `이`는 KS 표지만 있음) |
| `education` | 교육용 기초한자(`E`)면 `Y` |
| `koreanname_year` | `kKoreanName` 연도(2015/2018). 교육용 전용 글자는 빈칸 |
| `radical_no` | 원획 계산에 **실제로 쓴** 강희 부수 번호(기본은 `kRSUnicode` 첫 값. 바뀐 경우 `wonhoek_rule` 플래그로 표시) |
| `radical_simplified` | 그 부수가 간화 자형(아포스트로피)이면 `Y` |
| `residual` | 원획 계산에 실제로 쓴 나머지 획수 |
| `unicode_total_strokes` | `kTotalStrokes` 첫 값 |
| `wonhoek` | 성명학 원획 |
| `wonhoek_rule` | 원획을 정한 규칙, 그리고 `\|`로 이은 플래그(4절) |
| `hoek_ohaeng` | 원획 끝자리 오행: 1·2 木 / 3·4 火 / 5·6 土 / 7·8 金 / 9·0 水 |
| `radical_ohaeng` | 부수 자원오행 **휴리스틱**(5절). 출처가 갈리면 `金/土`처럼 둘 다 적음. 관행이 없으면 빈칸 |
| `definition_en` | Unihan 영문 뜻 |
| `radical_char` | 부수 정자(예: 85 → 水) |
| `dueum_readings` | 인명용 읽기에 두음법칙(한글 맞춤법 제10~12항)을 적용한 변형(예: 李 `이`, 林 `임`, 樂 `낙`) |
| `khangul_raw` | `kHangul` 원문(표지 포함) |
| `hun` | libhangul 훈음. 인명용 읽기 순서로 정렬하고 `/`로 구분 |

## 4. 원획 규칙

기호: K = 강희 부수 **정자** 획수 + 나머지 획수, T = 유니코드 총획.

한국 성명학의 원획법은 강희자전 획수를 기준으로 하고, 약자로 쓰는 부수를 정자 획수로 되돌린다. 아래 13개 부수가 그 대상이며, 각 값은 강희 부수 자체의 획수와 같다.

> 水(氵)=4, 手(扌)=4, 心(忄)=4, 犬(犭)=4, 玉(王)=5, 示(礻)=5, 衣(衤)=6, 艸(艹)=6, 肉(月 육달월)=6, 辵(辶)=7, 邑(阝 오른쪽)=7, 阜(阝 왼쪽)=8, 网(罒)=6

| 규칙 | 행 수 | 내용 |
|---|---:|---|
| `unicode-total` | 5,585 | K = T. 그대로 씀. 이미 정자 부수로 쓰인 글자 포함(泉, 志, 忠) |
| `radical-full` | 2,038 | 위 13개 부수에서 K > T. 정자로 환산(河 8→9, 道 13→16, 英 9→11, 育 8→10) |
| `kangxi-sum` | 397 | 다른 부수에서 K > T. 부속 성분을 현대 자형이 덜 센 경우(權 21→22, 娜 9→10, 健 10→11). 부수 老(125)가 耂(4획)로 쓰이면 4획으로 셈 |
| `total-gt-rs-check` | 56 | T > K. T를 쓰고 옥편 확인을 권함(成 7, 興 16, 紫 12, 者 9) |
| `radical-variant-check` | 3 | 13개 부수가 더 긴 변형으로 쓰여 T > K. T를 씀(求·泰의 氺, 滕) |
| `radical-itself-check` | 1 | 才(手部 0획). 글자 자체가 독립 자형이라 T=3을 씀. 王은 Unicode가 `96.-1`로 적어 4획이 그대로 나옴 |
| `numeral-meaning` | 10 | 一~十은 의미수 1~10 |
| `override` | 4 | 대만 자형 때문에 T가 큰 예외: 延 7, 筵 13, 御 11, 禦 16(사유는 스크립트 `OVERRIDES`에 있음) |

### 강희자전 위치 보정 (`kKangXi`)

강희자전은 부수, 그다음 나머지 획수 순으로 글자를 배열한다. 실제 수록자 가운데 RS 값이 하나뿐인 약 4만 자를 참조열로 삼는다. 각 글자에 대해 앞뒤 이웃 4자의 최빈 부수와 나머지 획수를 보고, 그 글자가 놓인 강희 구간을 추정한다.

- **RS 후보가 여럿인 글자**: 강희 구간에 맞는 후보를 고른다(`rs-by-kangxi-pos`, 18자). 예를 들면 萬은 禸 대신 艸 → 15, 蒸은 火 대신 艸 → 16, 巡은 辵 대신 巛 → 7, 尹은 尸 → 4, 睡는 109.8 → 13, 琉는 96.7 → 12, 猪는 94.9 → 13, 卿은 26.10 → 12다.
- **확정 구간의 나머지 획수가 유니코드 값보다 클 때**: 강희 값으로 올린다(`kangxi-pos-residual`, 32자). 예(유니코드 총획→원획): 城 9→10, 誠 13→14, 著 13→15, 署 14→15, 響 20→22. 盛·暑는 보정 결과가 T와 일치한다. 다만 이 보정은 통계적 추정이다. 예컨대 異 11→12, 翼 17→18은 국내 옥편 값(11, 17)과 다를 수 있다.
- **강희 구간이 유니코드 값보다 작을 때**: 값은 그대로 두고 `kangxi-pos:<부수>.<lo>[-<hi>]` 플래그만 단다(41자. 예: 姬, 熙, 剩, 犀).

### 플래그 요약

| 플래그 | 건수 | 뜻 |
|---|---:|---|
| `component-kangxi-diff` | 138 | 약자 부수 환산분보다 K−T가 커서, 부속 성분의 획수 차이도 함께 반영됨(汲 8, 芝 10, 蓮 17, 瑛 14) |
| `kangxi-pos` | 41 | 강희 위치 추정과 쓰인 나머지 획수가 다름(정보용) |
| `kangxi-pos-residual` | 32 | 강희 위치로 나머지 획수를 올림 |
| `multi-rs` | 20 | 다른 RS 후보로 계산하면 원획이 달라짐 |
| `rs-by-kangxi-pos` | 18 | 첫째가 아닌 RS 후보를 채택 |

- 규칙이 `unicode-total`·`radical-full`·`numeral-meaning`이 아니거나 플래그가 하나라도 붙은 행: **660자**.
- 그중 옥편 대조를 권하는 행(`total-gt-rs-check`·`radical-variant-check`·`radical-itself-check`·`override` 규칙, 또는 `multi-rs`·`rs-by-kangxi-pos`·`kangxi-pos*` 플래그): **163자**.

### 검증

작명서와 성씨표에서 관행적으로 쓰는 원획 42자를 기준값으로 삼았다(`KNOWN_WONHOEK`).

> 金8 李7 朴6 崔11 鄭19 姜9 趙14 尹4 張11 林8 韓17 吳7 徐10 申5 權22 黃12 安6 宋7 劉15 洪10 瑞14 潤16 河9 沇8 昀8 垠9 尙8 忠8 炫9 娜10 延7 道16 英11 浩11 珍10 祐10 福14 裕13 育10 郁13 陽17 都16

결과는 **불일치 0건**이다. 단 延은 `override`로 맞춘 값이고, 규칙만 적용하면 8(T)이 나온다. 참고로, 약자 부수 환산만 하고 나머지는 유니코드 총획을 그대로 쓰는 단순 규칙이었다면 權 21, 娜 9, 延 8에서 어긋났을 것이다.

### 尙 / 尚

| 글자 | Unihan 값 | 이 표 |
|---|---|---|
| 尙 U+5C19 | `kHangul 상:0E`, K-source `K0-5F46`, 교육용(2007) | 있음. 원획 8 |
| 尚 U+5C1A | `kHangul` 없음, K-source 없음(`kKorean SANG`만 있음) | 없음 |

한국 표준 부호계(KS X 1001)와 인명용 한자표의 자형은 **尙(U+5C19)**이다. 이름을 입력할 때는 반드시 U+5C19가 들어갔는지 확인한다.

## 5. 부수 자원오행 휴리스틱 (`radical_ohaeng`)

한국 작명에서 자원오행은 글자마다 뜻까지 따져 정하는 경우가 많다. 그래서 부수만으로는 작명 프로그램의 값을 완전히 재현할 수 없다. 이 열은 원획 계산에 쓴 부수 하나만 보고 정한 **참고값**이다.

| 오행 | 부수(강희 번호) | 근거·비고 |
|---|---|---|
| 木 | 木75, 艸140, 竹118, 禾115, 米119, 糸120, 瓜97, 韭179, 麥199, 麻200, 黍202 | 나무·풀·곡식·실. 木·艹는 여러 자료에서 일치. 禾·米·糸 등은 식물성이라는 관행을 따름 |
| 火 | 火86(灬 포함), 日72, 赤155, 心61 | 火·日·赤는 자료에서 일치. **心→火는 관행 기반이며 신뢰도가 낮다.** 光은 儿부(10)라 부수로는 잡히지 않음 |
| 土 | 土32, 山46, 田102, 里166, 阜170, 邑163 | 흙·산·밭·언덕·고을. 阝 계열을 土로 보는 것은 관행 기반 |
| 金 | 金167, 刀18, 戈62, 斤69, 貝154 | 쇠·칼·창·도끼·재물. 刀는 자료에서 일치 |
| 水 | 水85(氵·氺), 雨173, 冫15, 巛47, 魚195 | 水·氵·雨·冫는 자료에서 일치 |
| 金/土 | 玉96 | 자료마다 다름: 金(귀금속·보석)으로 보는 곳과 土(琳을 土로 분류)로 보는 곳이 있음 |
| 土/金 | 石112 | 자료마다 다름: 土 쪽이 더 흔함 |
| (빈칸) | 그 밖(口, 人, 女, 月74, 言, 目 등) | 관행이 뚜렷하지 않음 |

결과 분포: 木 1,215 / 水 642 / 火 623 / 土 467 / 金 401 / 金·土 186 / 土·金 98 / 빈칸 4,462.

## 6. 한계와 주의

1. **대법원 목록과의 시차**
   - Unihan의 인명용 표지는 2018년 목록(`kKoreanName` 최대 2018)까지만 반영되어 있다.
   - 대법원은 인명용 한자를 8,319자에서 **9,389자로 1,070자 확대**했다. [법률신문 보도](https://www.lawtimes.co.kr/news/198522)에 따르면 6월 11일부터 시행했다(2024년 개정으로 알려져 있으나 연도는 대법원 공지로 다시 확인할 것). 이 추가분은 이 표에 **없다**.
   - 대법원 집계는 같은 글자를 발음별로 따로 세는 등 기준이 달라, 이 표의 8,094와 직접 비교할 수 없다.
   - 최종 판단은 항상 [대법원 인명용 한자 조회](https://efamily.scourt.go.kr/cs/CsBltnWrtList.do?bltnbordId=0000010)로 한다.
2. **읽기**
   - `inmyeong_readings`에는 Unihan이 `N`/`E` 표지를 붙인 읽기만 들어 있다.
   - 인명용 한자표 비고에는 첫소리 ㄴ·ㄹ 한자를 소리 나는 대로 ㅇ·ㄴ으로 쓸 수 있다는 취지의 규정이 있다. 이를 위해 `dueum_readings`를 따로 계산해 두었으나, 실제 허용 여부는 대법원 조회로 확인한다.
3. **원획**
   - 국내 옥편과 작명서 사이에도 획수가 갈리는 글자가 있다(姬 9/10, 熙 13/14, 才 3/4 등).
   - `wonhoek_rule`에 플래그가 붙은 글자는 이름 후보로 쓰기 전에 옥편으로 다시 확인한다.
   - `override`는 4자뿐이다. 규칙으로 해결되지 않는 예외가 더 있을 수 있다.
4. **훈음**: libhangul 사전의 훈음은 대법원이 지정한 훈이 아니다. 한 글자 항목이 없거나 뜻이 비어 있는 글자가 905자 있다(예: 昀, 姊, 晚).
5. **자원오행**은 5절의 휴리스틱이다. 작명 프로그램마다 값이 다를 수 있다.
6. **이 표가 판단하지 않는 것**: 이 표는 사용할 수 있는 글자의 범위와 획수만 다룬다. 성명학적 길흉은 판단하지 않는다.
